# Discord Bot（スマホから全部やる）

LINE Bot の置き換え。**毎日18:00にリサーチから動画1本を自動で作り、Discordに届ける**。
社長が「投稿」と送った時だけ、**YouTubeに予約投稿し、TikTokは貼る投稿文を出す**
（TikTokは手動投稿）。

LINE版と違って **cloudflaredトンネルも webhook登録も要らない**（Botが自分から
Discordに常時接続を張るため）。Macでこのプロセスが動いていればそれで完結する。

```
毎日18:00  ─┐
「作って」 ─┴→ ① リサーチ  TikTok検索→再生数/フォロワー取得→黄金式で選別
              ② 文字起こし whisper large-v3
              ③ 台本      季節性・角度の重複を判定 → 台本 → 整形 → キャプション  ★LLMはここだけ
              ④ 動画生成   VOICEVOX + ffmpeg（--title-lines 自動）
              ↓
         Discordにプレビュー動画＋投稿ボタンが届く
              ↓
    社長が「投稿」と送る／ボタンを押す  ← ここが唯一の人間ゲート
              ↓
         YouTube（翌朝6:30）に予約  ＋  TikTokの投稿文をコピペで渡す
              ↓
         TikTokは社長がアプリで手動投稿（目安 翌朝8:30）
```

## 初回準備（社長の作業）

### 1. Discord Botを作る
1. https://discord.com/developers/applications → **New Application**（名前は任意）
2. 左メニュー **Bot** → **Reset Token** → 出てきたトークンをコピー（後で `.env` に貼る）
3. 同じ Bot ページの **Privileged Gateway Intents** で
   **MESSAGE CONTENT INTENT を ON**（これが無いとメッセージを読めない）
4. 左メニュー **OAuth2 → URL Generator** で
   - SCOPES: `bot`
   - BOT PERMISSIONS: `Send Messages` / `Attach Files` / `Read Message History`
     / **`Create Public Threads`** / **`Send Messages in Threads`**
     （後ろ2つが無いと動画ごとのスレッドが立たず、全部チャンネルに直接流れる）
   - 生成されたURLを開いて、自分のDiscordサーバーに追加
5. Discordの設定→詳細設定→**開発者モードをON** → 使いたいチャンネルを右クリック→**チャンネルIDをコピー**

### 2. .env を作る
```bash
cd 統括/Discordbot
cp .env.example .env
```
`DISCORD_BOT_TOKEN` と `DISCORD_CHANNEL_ID` を記入する。

### 3. 常駐させる（初回に1回だけ）
```bash
cd 統括/Discordbot
./.venv/bin/python selftest.py   # 準備できてない項目を先に洗い出す
./install_agent.sh                # macOSの launchd に登録して起動する
./install_agent.sh status         # いま動いているか見る
```

**手で `./run.sh` して開けっぱなしにする運用はやめた。** ターミナルを閉じた・何かの
拍子に落ちた、で止まったままになり、2026-09-09の朝は6:00の自動生成が丸ごと飛んだ
（issue #3）。VOICEVOXもSSDも認証も全部生きていて、**Botが起動していなかっただけ**で
1日分の打席を落とした。落ちても気づけないのが一番まずい。

`install_agent.sh` は `~/Library/LaunchAgents/com.taisyoku.discordbot.plist` を書いて
`launchctl` に預ける。以後は **落ちても30秒で勝手に上がり、Macを再起動しても自分で戻る**。
定刻を寝過ごしても、**12時間以内なら起き上がった時点で追いかけて実行する**
（`bot.CATCHUP_LIMIT`）ので、朝落ちていて昼に復帰してもその日の1本は作られる。

#### ⚠ 先に `/bin/bash` へフルディスクアクセスを与える（1回だけ・社長の操作）

このプロジェクトは `~/Documents` の下にある。ターミナルから手で動かす分には通るが、
**launchd から起動したプロセスは `~/Documents` を一切触れない**（macOSのTCC）。
確認画面も出ず `Operation not permitted` で即死するだけなので、気づきにくい。

> システム設定 → プライバシーとセキュリティ → フルディスクアクセス
> → 「+」→ Cmd+Shift+G で `/bin/bash` を指定して追加 → スイッチをオン

そのあと `./install_agent.sh` を実行する。許可が無いままだと、スクリプトが
それを検知して登録を巻き戻し、上の手順を出して終わる（「登録できました」と言いながら
一度も起動していない、という一番困る状態を作らないため）。

plist の中身で効いているのは3つ:

- **`/bin/bash` 経由で `run.sh` を起動する** — フルディスクアクセスは「実行される
  バイナリ」に与えるもので、`~/Documents` の中のスクリプトはそもそも exec できない。
- **PATH を明示的に入れる** — launchd が渡す PATH は `/usr/bin:/bin:/usr/sbin:/sbin`
  だけ。ffmpeg も claude CLI も Homebrew 側に居るので、そのままだと
  「Botは起動するのに動画生成だけ落ちる」という分かりにくい壊れ方をする。
- **ログは `~/Library/Logs/discordbot.log`** — 出力先を `bot.log`（Documents配下）に
  すると、launchd がそのファイルを開けずに `EX_CONFIG` で即死する。

一時的に止める・外すとき:
```bash
./install_agent.sh off            # 常駐を外す（Botも止まる）
./run.sh                          # 常駐させずに手で起動（デバッグ時）
./stop.sh                         # 手起動を止める
```

`run.sh` は `.bot.pid` で**二重起動を防ぐ**。Botが2つ動くと1つのメッセージに2回返事をし、
18:00の自動実行も同時に2本走ってしまうため（実際に3つ起動して事故りかけた）。
PIDが生きているだけでなく**中身が本当にこのBotか**まで見る。`exec` でシェルごと
置き換わる関係で死んだPIDが `.bot.pid` に残り、それが別プロセスに再利用されると
「起動中」と誤判定して launchd が30秒ごとに空振りし続けるため。

前提: **VOICEVOX.app 起動中／外付けSSD「Extreme SSD」接続**（動画生成の依存）。
TikTok・YouTubeの認証は `4_投稿/scripts` の `login.py` / `youtube_auth.py` を各1回。

## Discordに送るコマンド

| 送る言葉 | 何が起きるか |
|---|---|
| `作って` | リサーチから全自動で1本（18:00の自動実行と同じ）。10〜20分 |
| `035 作って` | 用意済みの台本 `本番_035.txt` から動画だけ作る |
| TikTokのURLを貼る | その動画を参考に台本化→動画生成（リサーチ工程を飛ばす） |
| **`投稿`** | **YouTube（翌朝6:30）に予約。TikTokは投稿文をコードブロックで出すだけ（手動投稿・目安 翌朝8:30）** |
| **`おまかせ投稿`** | **TikTokもブラウザ自動化で確定まで押す（Macの前に居られない時用）** |
| `投稿 035` | 回を指定して投稿 |
| `夜 投稿` | 翌朝ではなく次の18:30に予約 |
| `毎日20時` | 自動実行の時刻を変更 |
| `自動オフ` / `自動` | 停止 / いまの設定を表示 |
| `分析` | 週次レビューを今すぐ回す（**毎週日曜22:00に自動で走る**） |
| `毎週日曜22時` | 週次レビューの曜日・時刻を変更 |
| `週次オフ` / `週次` | 停止 / いまの設定を表示 |
| `ヘルプ` `状態` | 使い方・状態 |

プレビューの下に出るボタンでも投稿できる。上段＝翌朝（**TikTok 8:30／YouTube 6:30**）／下段＝夜18:30、
**青＝TikTokは投稿文を出すだけ（手動投稿）／赤＝おまかせ（TikTokも確定まで自動）**。

ボタンは `discord.ui.DynamicItem`（`bot.add_dynamic_items(PostButton)`）なので
**Botを再起動しても、何日前のプレビューのボタンでも効く**。
ふつうの View はBotのメモリ上にしか無く、再起動すると過去のボタンが全部無反応になり
Discordに「⚠ <bot名> は時間内に応答しませんでした」と出る（2026-08-05に踏んだ）。

### 週次レビュー（毎週日曜22:00・分析→次の生成に自動反映）
`5_分析/scripts/weekly_review.py` を回し、結果をスレッドに書いて終わる。**投稿には触らない**。

1. `update_results.py` … 自分の投稿の再生数を取り直す（`5_分析/実績.tsv`）
2. 材料集め（`feedback_context.py`）＋ LLM **1回**（`5_分析/プロンプト_週次反映.md`）
3. **反映**: `1_リサーチ/検索語.json`（次のリサーチが探す語）と
   `2_台本生成/重点方針.md`（次の台本プロンプトに入る方針）を書き換える
4. **下書き**: `1_リサーチ/ネタ提案_YYYYMMDD.md`（採用/却下は社長）

機械が書き換えるのはこの2ファイルだけで、`台本作成ルール.md` やコードには触らない。
上書き前の値は週次レポート（`5_分析/レポート/週次_YYYYMMDD.md`）に丸ごと残るので git で戻せる。
実測の取り直しで投稿用プロファイルのChromeを開くため、生成・投稿とは同じロックで排他する。

### 完成したらメンションで呼ぶ

動画が出来て**あとは投稿だけ**になった時、プレビューのメッセージで社長を `@` で名指しする。
スマホの通知が鳴るので、18:00（現在は06:30）の自動実行に張り付いていなくても気づける。

- 鳴るのは**完成したとき（`作って`・自動実行・`直して`）だけ**。
  自分から `見せて` と言った時は目の前に居るので鳴らさない。
- 相手のIDは `.env` の `DISCORD_MENTION_USER_ID`（無ければ `DISCORD_ALLOWED_USER_ID`）。
  **どちらも空でよい** — 起動時にチャンネルの直近の発言者を社長として覚え、
  `state.json` の `owner_id` に残す。設定作業は要らない。
- 別の人を呼びたい／覚え違いを直したい時は `.env` に `DISCORD_MENTION_USER_ID` を入れるか、
  `state.json` の `owner_id` を消して再起動する。

### 動画1本＝スレッド1つ

毎朝の自動実行が同じチャンネルに流れ続けると「いつがどの動画か」が分からなくなるので、
**1本ごとにスレッドを立てる**。チャンネルに残るのは見出し1行だけ。

```
# 動画チャンネル
  🤖 06:30 自動実行 — 今日の1本を作ります
  └ ✅ 本番_037 会社が教えてくれない一括給付金3選      ← 完成時にBotが見出しに書き足す
    └ 🧵 08/05 #037 会社が教えてくれない一括給付金3選  ← 進捗・プレビュー・投稿結果は全部この中
  🤖 06:30 自動実行 — 今日の1本を作ります
  └ ✅ 本番_036 退職する人は全員知ってほしい給付金制度
    └ 🧵 08/04 #036 退職する人は全員知ってほしい給付金制度
```

- 作り始めは回番号が分からないので仮の名前で立ち、**完成した時点で回番号とタイトルが入る**。
  見分けがつく情報は必ず**チャンネル側の見出し**に書き足す（自分のメッセージの編集は
  権限に関係なく通るため）。スレッド名の付け替えは『スレッドの管理』権限がある時だけ効く
  ＝**無くても運用に支障はない**（あった方が一覧が読みやすい、程度）
- **スレッドの中でそのまま `投稿` `直して〜` と話しかけられる**（親チャンネル宛と同じ扱い）
- チャンネルで `投稿 036` と言っても、その回のスレッドに書きに行く（紐づけは `state.json` の `thread_id`）
- `直して` は新しいスレッドを立てずに元のスレッドに続ける
- 7日で一覧から畳まれるが消えない。書き込めば自動で開く
- 権限が無ければ**従来どおりチャンネルに直接書く**（作業は止めない・1回だけ警告が出る）

### TikTokは手動投稿（既定・2026-09-09〜）

TikTokだけ手動に戻した。ブラウザ自動化は規約がグレーな上、UI変更で静かに壊れる
（2026-08-20〜09-04は曲名の表示が変わったせいで**15本連続でBGM無しのまま公開**された）。
`投稿` でBotがやるのはYouTubeの予約までで、TikTokには一切触らない。

1. `投稿` と送る（またはプレビューの青いボタン）
2. YouTubeは予約完了。続けて **TikTok用の投稿文がコードブロックで1通届く**
3. その投稿文をコピーして、TikTokアプリ／Webから手動で投稿する
   （動画の実物パスも一緒に出る。目安の時刻は翌朝8:30）

投稿文を渡した時点で `4_投稿/ログ/post_log.csv` に `manual` 行を残す。
**5_分析 はこのキャプションで実測と回を突合している**ので
（`update_results.caption_index`）、ここが途切れると新しい回が `実績.tsv` に載らず、
週次レビューと `write_script.py` の勝ち筋判定が新しいデータを見なくなる。

Macの前に居られない時だけ `おまかせ投稿` と送れば、従来どおりChromeを開いて
確定まで自動で押す（この時だけ日付ズレの目視確認の警告が出る）。

## 設計上の約束

- **投稿は必ず人間の合図が要る。** 自動実行がやるのは「作って見せる」まで。
  何も言わなければ何も投稿されない。
- **タイトルが壊れる形なら動画を作らせない。** `runner.title_problems()` が
  「フック1文目が2〜3行」「`--title-lines` が1文目の行数と一致」を検査し、
  外れていれば `make_video` が生成を拒否してDiscordに理由を出す。
  タイトルは一番壊れやすく、壊れたまま完成すると人が気づくまで分からないため
  （実績: 本番_036=バラけて1行／本番_032=2文目が混ざる）。
  プレビューには**タイトルカードの静止画とタイトル行**を必ず添付する。
- **LLMを叩くのは1本につき1回だけ**（`write_script.py`）。季節性判定・台本・
  キャプションを1つのプロンプトにまとめてある。既定は契約済みの `claude` CLI＝
  追加課金なし。尺が75秒を超えた時だけ、詰め直しでもう1回だけ叩く。
- **生成と投稿は同時に走らない**（`_busy` ロック）。ChromeとVOICEVOXが競合するため。
- **工程エラー時はCodexが自動で調査・修正する。** APIは使わず、このMacで
  ChatGPTログイン済みの `codex` CLIだけを非対話実行する。修正結果は同じDiscord
  スレッドへ返る。投稿・アップロードはCodexに許可しない。止めたい場合は `.env` に
  `AUTO_CODEX_RESCUE=0`、待ち時間は `CODEX_RESCUE_TIMEOUT=1800`（秒）で変更できる。
- **生成がコケたら人を待たずに作り直す**（2026-08-17）。Codexが直す →
  Botが自分の `config`/`runner`/`pipeline` を読み直す → もう一度作る、を
  `AUTO_RETRY_MAX`（既定2）回まで。工程スクリプトは subprocess なので毎回新しい
  ものが動くが、Botが抱えているモジュールは読み直さないと直した意味が無い
  （実際に「直したのに同じエラー」が起きた）。**`bot.py` 自身が直された時だけは
  再起動が要る**のでその旨をDiscordに出す。コードが直らなかった時
  （TikTok側の一時制限など）は `AUTO_RETRY_WAIT`（既定300秒）空けてから試す。
  **投稿はこの対象外**＝失敗しても勝手にやり直さない。
- 候補が季節ネタ・既出角度だった場合は `採用履歴.tsv` に【不採用】と書き戻して
  次の候補へ進む（30日の再利用ロックは残す）。手運用と同じ作法。

## 詰まったら

| 症状 | 対処 |
|---|---|
| Botが反応しない | MESSAGE CONTENT INTENT がONか。`DISCORD_CHANNEL_ID` が合っているか |
| 朝に何も届かない | `./install_agent.sh status` で生死を見る。🔴なら `./install_agent.sh` で入れ直す。原因は `bot.log` の末尾 |
| 「候補がゼロ」 | TikTokに一時的にブロックされている。時間を空けるか、URLを直接貼る |
| 動画生成で失敗 | VOICEVOX.app が起動しているか、外付けSSDが繋がっているか |
| 台本が長い/短い | `2_台本生成/台本作成ルール.md` を直す（プロンプトはこれを丸ごと読んでいる） |
| プレビューが添付されない | 8MBを超えた場合。実物のパスがメッセージに出るのでそれを見る |
