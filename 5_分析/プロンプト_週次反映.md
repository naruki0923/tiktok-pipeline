# プロンプト_週次反映（5_分析 → 1_リサーチ / 2_台本生成）

`weekly_review.py` が毎週日曜22:00にLLMへ渡す指示書。**呼び出しは週1回・1本だけ**
（メモリ llm-cost-minimize-claude-cli）。材料集め・反映・通知はスクリプト側でやるので、
ここで求めるのは「実測から何を変えるか」の判断だけ。

> **自動で反映されるのは検索語と重点方針の2つだけ。** ネタ提案は今までどおり下書きで、
> 採用/却下は社長（メモリ act-step-human-gate）。台本作成ルール.md 本体は書き換えない。

## 判断の土台（ここを外さない）
- **再生を決めるのはネタ**。維持率と再生数はほぼ無相関（メモリ topic-drives-views-not-retention）。
  だから変えるのは「何を語るか」であって、テンポや尺の微調整ではない。
- **再生は投稿後30日伸び続ける**。公開7日未満の本数で「沈んだ」と決めない。
- **視聴者は55歳以上が約7割**。年齢トリガー（60歳・65歳）と「取られるお金を減らす」が当たり筋。
- **1行目の数字は年齢・期限・日数**。金額の大きさは効かない。
- 景表法・誇大表現NG（「必ずもらえる」等の断定、額面の煽り）。

## 出力（JSONのみ。前後に説明文を書かない）
```json
{
  "summary": ["Discordに出す要点。1行40字程度で3〜6行。数字を入れて具体的に"],
  "keywords": ["auto_research.py に渡す検索語。4〜8語。1語20字以内"],
  "focus": "台本を書くLLMに毎回渡す『今週の重点方針』。Markdown。600字以内",
  "proposals": "1_リサーチ/ネタ提案_YYYYMMDD.md の本文。Markdown。3〜5案＋承認欄",
  "notes": "反映を見送ったこと・社長に判断してほしいこと。無ければ空文字"
}
```

### summary
今週の実測で何が起きたか。**先週から何を変えるか**を必ず1行入れる。
例: 「65歳トリガーが3本連続で1万超え。年齢入口を今週も継続」

### keywords（＝リサーチに直接反映される）
- 伸びた角度に**近い検索語**を厚めに、沈んだ角度の語は落とす。
- 参考動画が見つからないと1本も作れないので、**幅を捨てすぎない**（少なくとも2語は
  「退職給付金」「失業保険」級の広い語を残す）。
- 前回の検索語をそのまま出してよい（変える理由が無いなら変えない）。

### focus（＝台本プロンプトに直接反映される）
`write_script.py` が毎回の台本生成プロンプトに丸ごと差し込む。だから
**書き手への指示文**として書く（分析の感想文にしない）。含めるもの:
- 今週優先する入口（年齢・期限・対象者）を2〜3個、実績の再生数つきで
- 今週は書かない型を1〜2個、理由つきで
- 1行目（フック）の作り方の指定を1行

### proposals
`プロンプト_フィードバック.md` の出力フォーマットに従う。各案に
`[ ] 採用   [ ] 却下` を付け、末尾に「── 以下、社長の承認欄 ──」を置く。
