# プロンプト_フィードバック（5_分析 → 1_リサーチ）

AI（Claude）が「次に何を作るべきか」を提案する工程の指示書。
`feedback_context.py` が集めた材料束を読み、この指示に従って
`1_リサーチ/ネタ提案_YYYYMMDD.md` に**下書き提案**を書く。

> **大前提: これは提案まで。採用/却下は社長（人間承認ゲート）。**
> AIが勝手に台本化・投稿へ流してはいけない。社長がOKした案だけ次工程（use_ref.py 等）へ。

## 入力
1. `feedback_context.py` の出力（材料束。`--md` で保存したファイルでも可）
2. 参考: `1_リサーチ/参考動画リスト.md`（候補・見送り欄まで読む）、過去台本 `2_台本生成/台本_*.txt`

## 手順
1. 材料束の **「0. データ充足度」のモード**をまず確認し、そのモードの上限を守る。
   - 🅐 一般論 / 🅑 僅少 → **断定しない。「仮説」「試す価値のある型」として出す。**
   - 🅒 初期 / 🅓 データ駆動 → 自データの勝ち動画の共通項を根拠に提案してよい。
2. 「1. 自動判定レポート」で勝ち/要改善を確認。勝ちがあれば**その型・フック・テーマを横展開**、
   要改善は原因（フック/尺/テンポ）を次案でどう直すか書く。
3. 「2. 投稿済みの訴求」と「4. 過去台本のフック」を見て、**既出の切り口と丸かぶりを避ける**
   （同じフック連発は飽きられる。角度を変える）。
4. 「3. 採用履歴（30日ロック）」で**🔒ロック中の参考動画は使わない**。✅解除済みと未採用から選ぶ。
5. 「5. 参考動画プール」の候補・見送り欄から、まだ使っていない勝ち型を拾う。

## 出力する提案（3〜5案）
各案に必ず含める:
- **狙う型/フック**（例: 【永久保存版】＋「全員〜してください」命令形で保存を煽る）
- **テーマ/切り口**（退職給付金のどの制度・どの悩みに刺すか）
- **根拠**（どの参考動画/どの自データから。モードに応じて仮説 or 実測）
- **LINE導線への繋げ方**（無料説明会へどう自然に落とすか。落とせない案は出さない）
- **推奨アクション**（採用するなら → 使う参考動画URL（あれば）を明記。無ければ「新規構成」）

## 守る制約（CLAUDE.md / メモリ準拠）
- **景表法・誇大表現NG**: 「必ずもらえる」「◯◯万◯」等の断定的な額面訴求を提案に含めない。
  参考動画に額面訴求があっても、そのまま横展開せず**事実ベースに言い換える案**にする（リーガルチェック方針）。
- **30日再利用ルール**: ロック中の参考動画を採用案に出さない。
- **提案は下書き**: 最後に「── 以下、社長の承認欄 ──」を付け、各案に `[ ] 採用 / [ ] 却下` を置く。

## 出力フォーマット（`1_リサーチ/ネタ提案_YYYYMMDD.md`）
```markdown
# ネタ提案 YYYY-MM-DD（データ充足度: 🅐/🅑/🅒/🅓）

> 5_分析 の材料束をもとにAIが作成した下書き。採用/却下は社長。

## 提案一覧
### 案1: <タイトル/フック>
- 型: …
- テーマ: …
- 根拠: …（仮説 or 実測◯本ベース）
- LINE導線: …
- アクション: 採用時 → use_ref.py "<URL>" / または新規構成
- [ ] 採用   [ ] 却下

### 案2: …
（同様に3〜5案）

## 総括（次の1本の推し）
- いま最優先で試すべきは 案X。理由: …
```
